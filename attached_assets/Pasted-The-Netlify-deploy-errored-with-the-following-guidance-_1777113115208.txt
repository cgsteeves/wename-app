The Netlify deploy errored, with the following guidance provided:

**Diagnosis**
- `pnpm run typecheck:libs` fails inside the `artifacts/wename` workspace because TypeScript cannot resolve `@react-navigation/bottom-tabs` used in `app/(tabs)/_layout.tsx`.
- `app/(tabs)/settings/profile.tsx` reads properties from `user` even when `user` can be `null`, triggering `TS18047`.
- `app/auth/callback.tsx` passes a value of type `MobileOtpType | EmailOtpType` to the email-only overload of `supabase.auth.verifyOtp`, leading to `TS2345`.
- `components/AuthContext.tsx` chains `.catch()` on the synchronous result of `supabase.auth.onAuthStateChange`, yielding `TS2551`.
- The files under `supabase/functions/*` import Deno-specific modules/globals (e.g., `jsr:` specifiers and `serve`), which Node’s `tsc` (run by the build) cannot resolve, producing multiple `TS2307`/`TS2304` errors.

**Solution**
- Install the missing navigation package so `_layout.tsx` can resolve it:
  ```bash
  cd artifacts/wename
  pnpm add @react-navigation/bottom-tabs
  ```
  Commit the updated `package.json` and lockfile.
- In `app/(tabs)/settings/profile.tsx`, add a guard (e.g., `if (!user) return null;`) or use optional chaining before accessing `user`’s properties so `user` is never `null` when dereferenced.
- In `app/auth/callback.tsx`, narrow the value passed to `supabase.auth.verifyOtp` to the email overload (e.g., only call it when `type` is an `EmailOtpType`, or dispatch `'sms'` to the mobile overload) so the argument matches the expected type.
- Replace the `.catch()` call on the result of `supabase.auth.onAuthStateChange` in `components/AuthContext.tsx` with a `try/catch` (or handle the returned `{ data, error }`) since the function returns a synchronous subscription, not a promise.
- Exclude the Supabase edge functions from the Node TypeScript project (or give them a separate Deno-specific configuration) so the Node compiler stops trying to resolve Deno imports/globals. For example:
  ```jsonc
  // artifacts/wename/tsconfig.json
  {
    "extends": "./tsconfig.base.json",
    "exclude": ["supabase/functions"]
  }
  ```
  Keep a separate `deno check` or Supabase-specific tsconfig for those files if you still want type safety there.

After applying the above, re-run `pnpm run typecheck:libs` locally to confirm the build succeeds before pushing.
