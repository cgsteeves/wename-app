================================================================================
SECTION 1 — WHERE PROFILE LIVES IN THE APP
================================================================================

The Profile page is a sub-page of Settings, not a standalone route.

Navigation path:
  Bottom Nav "Settings" tab
    → SettingsPage renders SettingsHub
    → User taps the "Profile" row in the "Your Account" section
    → activePage becomes 'profile'
    → SettingsPage renders ProfilePage

Back navigation:
  Tapping the back button in SubPageHeader calls onBack()
  → activePage becomes null → SettingsHub re-renders

There is NO slide or fade animation between settings pages. The swap is instant.

The Profile row in the Hub shows a summary beneath the title:
  If user.display_name is set:  shows user.display_name
  If user.display_name is null or empty:  shows "Set up your profile"
  This summary updates immediately after a successful save.

SECTION 8 — CHANGE DETECTION
================================================================================

The Save Changes button is ONLY enabled when at least one field has changed
from its persisted value. This is computed as:

  hasChanges =
    displayName !== (user.display_name || '')
    OR babyLastName !== (user.baby_last_name || '')
    OR babyGender !== user.baby_gender

This comparison is evaluated on every render (not debounced).
The button enables/disables instantly as the user types or toggles gender.

Note: the gender comparison is strict equality. If user.baby_gender is 'boy'
and the user taps 'boy' again (no actual change), hasChanges remains false.

================================================================================
SECTION 10 — SAVE ACTION AND DATABASE PERSISTENCE
================================================================================

Triggered by tapping the Save Changes button when it is ENABLED.

LOCAL STATE TRANSITIONS:
  saving = true   (button shows "Saving...", disabled)

DATABASE WRITE:
  UPDATE users
  SET
    display_name = displayName,
    baby_last_name = babyLastName,
    baby_gender = babyGender
  WHERE id = user.id
  RETURNING *

The update is done via updateUser({ display_name, baby_last_name, baby_gender }):
  1. supabase.from('users').update(updates).eq('id', user.id).select().single()
  2. If successful: setUser(data) — the global user state is updated with
     the full returned row. This updates the app-wide user object used by
     ALL components (swipe deck gender filter, partner page name display, etc.).
  3. If error: logs to console. The local form state is NOT reverted — the
     user's typed values remain in the inputs so they can try again.

AFTER SAVE:
  saving = false
  saved = true    (button shows "Saved!" for 2 seconds)
  After 2 seconds: saved = false

IMMEDIATE SIDE EFFECTS of saving:
  1. Baby gender change affects the swipe deck: the get_swipeable_names RPC
     uses the user's baby_gender to filter names. The swipe queue will
     re-initialize on next load with the new gender filter.
  2. Baby last name change affects swipe cards: the last name appears on every
     swipe card, so it updates immediately on the next swipe session.
  3. Display name change affects the Partner page: the partner sees the updated
     name the next time they load their Partner page (fetched fresh from DB).
  4. The Settings Hub summary for the Profile row updates immediately because
     the hub re-renders with the new user object.

--- RESET SWIPES BEHAVIOR ---

On press:
  1. Show native browser confirm dialog:
     Message: "Are you sure you want to reset all your swipes? This cannot be undone."
     Two buttons: "Cancel" and "OK"

  2. If user taps CANCEL:
     Nothing happens. Page state unchanged.

  3. If user taps OK (confirms):

     DATABASE OPERATION:
       DELETE FROM swipes
       WHERE user_id = me AND liked = false
     
     This deletes ONLY passes (liked=false).
     Liked names (liked=true) are NOT deleted — "Your Picks" is preserved.
     This means the user will see previously-passed names again in the swipe deck,
     but their favorited names remain in the Names section.

     LOCAL STORAGE CLEAR:
       localStorage.removeItem('swipe_session_v2_{user.id}')
     
     This key stores the current swipe deck position (currentIndex) and
     swipe history for the undo feature. Clearing it resets the deck
     back to position 0 on the next swipe session.

     FEEDBACK:
       Show native browser alert: "Swipes reset successfully!"
       window.location.reload()  — hard page reload to re-initialize everything

     ON ERROR:
       Log to console.
       Show native browser alert: "Failed to reset swipes"
       Page is NOT reloaded.

SECTION 14 — COMPLETE DATA MODEL (RELEVANT COLUMNS)
================================================================================

The three editable fields map directly to these columns on the public.users table:

  display_name     text    nullable     User's chosen name, shown to partner
  baby_last_name   text    nullable     Optional last name appended on swipe cards
  baby_gender      text    nullable     'boy' | 'girl' | 'either'
                           CHECK constraint on DB: ('boy', 'girl', 'unknown', 'either')

The reset swipes operation touches:
  swipes.liked     boolean              DELETE rows WHERE liked=false (passes only)

LocalStorage keys touched:
  'swipe_session_v2_{userId}'           Cleared on reset to reset swipe deck position
  'baby_picker_user_id'                 NOT touched — user identity preserved

================================================================================
SECTION 15 — COMPLETE STATE VARIABLES
================================================================================

Local React state (persisted only in component memory, reset on back navigation):

  displayName:  string  — controlled value for "Your Name" input
  babyLastName: string  — controlled value for "Baby's Last Name" input
  babyGender:   'boy' | 'girl' | 'either'  — selected gender option

  saving:  boolean  — true while the DB update is in flight
  saved:   boolean  — true for 2 seconds after a successful save

Derived values (computed, not stored):

  hasChanges:  boolean
    = displayName !== (user.display_name || '')
      || babyLastName !== (user.baby_last_name || '')
      || babyGender !== user.baby_gender
