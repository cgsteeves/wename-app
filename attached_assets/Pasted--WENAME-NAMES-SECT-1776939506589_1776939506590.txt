WeName baby name app. Everything in here is sourced directly from production
code. No value should be guessed or approximated. An AI following this
document should be able to produce a pixel-exact, behavior-exact replica.

--- REAL-TIME SUBSCRIPTION ---

When activeSubTab='matches' AND user.partner_id is set:
  Subscribes to public.matches table changes:
    Filter A: user_a_id=eq.{user.id}
    Filter B: user_b_id=eq.{user.id}
  Events: INSERT, UPDATE, DELETE
  On any event: reload the matches list from Supabase
  Channel name: "namesview-matches:{user.id}"

Subscription lifecycle:
  Created on mount of matches tab (useEffect watching activeSubTab).
  Destroyed via cleanup when activeSubTab changes, partner is removed, or
  component unmounts (supabase.removeChannel(channel)).

PART 8 — DRAG-TO-REORDER MECHANICS (DraggableList)
================================================================================

This is a custom drag-to-reorder implementation (no library dependency).
Both Your Picks and Shared Matches use DraggableList.

--- THE GHOST ELEMENT ---

When dragging starts, an absolutely positioned "ghost" copy of the dragged item
is created at z-index 50, opacity 0.90.
  position: absolute, left: 0, right: 0
  top:    = ghostY (the current Y position of the drag)
  height: = ghostHeight (height of the item being dragged)

The ghost is rendered by calling renderItem with isDragging=true.
  When isDragging=true the item shows shadow-xl and scale 1.02.

The original item in the list becomes visibility:hidden (layout preserved, not removed).

--- ITEM DISPLACEMENT ---

Items that need to shift out of the way animate with:
  transition: transform 150ms ease

Displacement distance = ghostHeight + 6 (the item height plus the gap between items).

Direction rules:
  If dragging DOWN (draggingIndex < dragOverIndex):
    Items between (draggingIndex+1) and dragOverIndex shift UP by -step
  If dragging UP (draggingIndex > dragOverIndex):
    Items between dragOverIndex and (draggingIndex-1) shift DOWN by +step

--- AUTO-SCROLL ---

When the drag enters within 60px of the container's top or bottom edge,
the container scrolls automatically at 6px per 16ms (≈375px/sec).
The scroll stops when the drag leaves the zone.

--- REORDER COMMIT ---

On drag end:
  1. Calculate from (original index) and to (final hover index).
  2. If from !== to: splice the array and call onReorder(newItems).
  3. Parent (NamesView) receives the new order and:
     a. Sets local state immediately.
     b. Iterates through all items and calls:
        UPDATE swipes/matches SET ranking = i+1 WHERE id = item.id
        for each item at index i.
     c. If any DB update fails: reloads from Supabase to revert.

================================================================================
PART 12 — ADD NAME FLOW (DETAILED BEHAVIOR)
================================================================================

--- YOUR PICKS ---

1. User taps "Add name" → addingName becomes true, inline form appears.
2. User types a name and selects gender (defaults to user's baby_gender preference).
3. Duplicate check (before any DB write):
   - if name text (case-insensitive) AND gender match any existing swipe:
   - setAddError('"Oliver" is already in your picks as a boy name.')
   - Do NOT close form, do NOT add.
4. If no duplicate:
   - Add an optimistic entry to swipes list immediately (local=true, id='local-xxx')
   - Close the form (addingName=false, newNameText='')
   - In background:
     a. Query names table for exact match (name + gender).
     b. If not found: INSERT into names (user_created=true, created_by_user_id=user.id).
     c. INSERT into swipes (user_id, name_id, liked=true).
     d. Replace optimistic entry with real DB entry (id, ranking from DB).
     e. Show toast: "{name} added"
   - On DB error:
     - Remove optimistic entry
     - Re-open form with the typed name pre-filled
     - Show error in form

--- SHARED MATCHES ---

Same flow but inserts into matches table:
  user_a_id = min(user.id, partner.id) (lexicographic sort)
  user_b_id = max(user.id, partner.id)
  gender = selectedGender

--- FROM AI SUGGESTIONS ---

1. User taps "+ Add to My Picks" on a suggestion card.
2. Button immediately shows "Added" state (local optimistic).
3. Name is added to allSwipedNames (so AI won't re-suggest it).
4. Toast: "{name} added to Your Picks!"
5. Background: query/insert names table, insert swipes row.
6. Swipes list updated (optimistic replaced with real row).
7. On error: revert button, remove from swipes list, toast "Failed to add {name}".
