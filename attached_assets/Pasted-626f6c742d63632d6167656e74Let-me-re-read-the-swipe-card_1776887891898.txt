PART 3 — DRAG GESTURE SYSTEM
================================================================================

--- 3.1 CONSTANTS ---

SWIPE_THRESHOLD_RATIO = 0.27
  The fraction of screen width the card must travel to commit a swipe.
  Example: on a 390px screen, threshold = 390 * 0.27 = ~105px

VELOCITY_THRESHOLD = 600
  Pixels per second. A fast flick above this speed commits a swipe even if
  the distance threshold was not reached.

MAX_ROTATION = 18
  Maximum degrees of rotation at full drag offset.

--- 3.2 THE DRAG LAYER ---

A separate invisible motion element sits BETWEEN the background image and the
card content (z-index 10).

  Position: absolute, inset-x: 0, top: 0, bottom: 128 (bottom-32)
  The bottom gap prevents the drag layer from blocking the action buttons.
  drag: "x" (horizontal only)
  dragConstraints: { left: 0, right: 0 } (rubber-band effect from origin)
  dragElastic: 0.18 (18% elastic resistance beyond constraints)
  dragMomentum: false (momentum is handled manually)
  touchAction: "pan-y" (allows vertical scrolling on touch devices)
  cursor: grab / grabbing

The drag layer is HIDDEN when the info overlay is open (so dragging on the info
panel does not also drag the card underneath).

--- 3.3 MOTION VALUES UPDATED DURING DRAG ---

x: tracks the raw horizontal offset in pixels.

rotate: interpolated from x
  inputRange:  [-screenWidth*0.6, 0, screenWidth*0.6]
  outputRange: [-18, 0, 18]  (degrees)
  The card tilts as you drag, up to ±18 degrees.

cardOpacity: interpolated from x
  inputRange:  [-screenWidth*0.6, -THRESHOLD*0.5, 0, THRESHOLD*0.5, screenWidth*0.6]
  outputRange: [0.55, 0.90, 1.0, 0.90, 0.55]
  The card fades slightly as it moves toward the edges.

likeOpacity: interpolated from x (right drag)
  inputRange:  [0, THRESHOLD*0.5, THRESHOLD]
  outputRange: [0, 0.7, 1.0]

likeScale: interpolated from x (right drag)
  inputRange:  [0, THRESHOLD]
  outputRange: [0.7, 1.15]

passOpacity: interpolated from x (left drag)
  inputRange:  [-THRESHOLD, -THRESHOLD*0.5, 0]
  outputRange: [1.0, 0.7, 0]

passScale: interpolated from x (left drag)
  inputRange:  [-THRESHOLD, 0]
  outputRange: [1.15, 0.7]

dragProgress (shared with back card): set to min(|x| / THRESHOLD, 1)
  0 = card at rest, 1 = card at or past the swipe threshold

--- 3.4 WHAT HAPPENS DURING DRAG ---

onDragStart:
  isDragging.current = true
  hasCommitted.current = false
  (Reset the commit guard so a new swipe can begin)

onDrag:
  x.set(info.offset.x)  — updates all interpolated values reactively
  dragProgress.set(min(|offset| / THRESHOLD, 1))

onDragEnd:
  isDragging.current = false

  Evaluate whether to commit or spring back:
    pastDistanceThreshold = |offset| > THRESHOLD
    pastVelocityThreshold = |velocity| > 600

    If NEITHER threshold passed:
      → Spring the card back to x=0
      → dragProgress.set(0)
      → hasCommitted.current = false
      → Done. Card returns to center.

    If EITHER threshold passed:
      Determine direction:
        liked = offset > 0
               OR (|offset| <= 10 AND velocity > 0)
        (The second condition handles a very fast flick where the card barely moved)
      → Call commitSwipe(liked, velocity)

--- 3.5 commitSwipe — THE SWIPE COMMIT ---

Guards against double-firing:
  if (hasCommitted.current) return
  hasCommitted.current = true

Calculate exit trajectory:
  direction = liked ? 1 : -1
  velocityBonus = min(|velocityX| / 1000, 1.8)
    This scales 0–1.8 based on how fast the flick was, maxing at ~1800 px/s.
  exitX = direction * screenWidth * (1.8 + velocityBonus * 0.6)
    At zero velocity: card exits to 1.8x screen width
    At max velocity:  card exits to 2.88x screen width
  duration = max(0.22, 0.42 - velocityBonus * 0.1)
    At zero velocity: 0.42 seconds
    At max velocity:  0.22 seconds (faster exit for fast flicks)

Haptic feedback:
  Trigger a 12ms vibration (navigator.vibrate(12) on web, expo-haptics on native)

Animate card off screen:
  Animate { x: exitX, opacity: 0 }
  Type: tween
  Duration: calculated above
  Easing: cubic-bezier(0.25, 0.46, 0.45, 0.94)  — ease-out

dragProgress.set(1)  — immediately bring back card to full size

Notify parent:
  After (duration * 1000 * 0.55) milliseconds (55% into the animation):
    Call onSwipe(liked)
  The 55% timing means the card is visibly off screen before the state updates,
  preventing a jarring flicker of the new card appearing.

--- 3.6 BUTTON-TRIGGERED SWIPE ---

The Pass (✕) and Like (Heart) buttons call triggerSwipe(liked):
  triggerSwipe(liked) → commitSwipe(liked, velocityX=0)

This uses zero velocity, so:
  velocityBonus = 0
  exitX = direction * screenWidth * 1.8
  duration = 0.42 seconds

The animation is the same physics — the card flies off screen. The only
difference from a gesture swipe is the slower, more graceful exit (no velocity
bonus).

--- 3.7 UNDO ---

The undo button calls onUndo() which lives in SwipeView (the parent).
The NameCard itself has no undo logic — it only provides the UI element.

Undo is enabled (canUndo=true) when:
  - swipeHistory.length > 0 (swiped at least once this session)
  - AND currentIndex > 0 (not on the very first card)

Undo does NOT animate the card. It simply:
  1. Deletes the swipe row from Supabase.
  2. Deletes any match that was created (if the undone swipe was a like and partner exists).
  3. Decrements currentIndex by 1.
  4. Removes the last entry from swipeHistory.
The previous card re-appears instantly (React state update, no animation).

================================================================================
PART 7 — THE COMPLETE GESTURE-TO-ANIMATION LIFECYCLE
================================================================================

This is the full sequence of events for a complete swipe:

1. USER PUTS FINGER DOWN
   onDragStart fires:
     isDragging.current = true
     hasCommitted.current = false

2. USER DRAGS
   onDrag fires repeatedly:
     x updates → rotate, cardOpacity update via interpolation
     dragProgress updates → back card scale/translateY update
     likeOpacity/passOpacity/likeScale/passScale update
     The sun image and text stamp fade in on the appropriate corner

3a. USER RELEASES (not past threshold)
   onDragEnd fires:
     pastDistanceThreshold = false
     pastVelocityThreshold = false
     x.set(0) → card springs back to center
     dragProgress.set(0) → back card returns to peeking position
     All opacity/scale values return to resting state
     hasCommitted remains false

3b. USER RELEASES (past threshold) or BUTTON PRESSED
   onDragEnd fires (or button calls triggerSwipe):
     commitSwipe(liked, velocity) called
     hasCommitted.current = true  ← guard prevents double-fire
     velocityBonus calculated from velocity
     exitX = direction * screenWidth * (1.8 + velocityBonus * 0.6)
     duration = max(0.22, 0.42 - velocityBonus * 0.1)
     HAPTIC: 12ms vibration fires
     dragProgress.set(1)  ← back card jumps to full size
     Card animates to exitX with opacity 0, using cubic-bezier tween
     At 55% of animation duration:
       onSwipe(liked) called in parent
       Parent increments currentIndex
       Next name is now the front card
       The card that was "back" is now "front" (key change → re-mounts fresh)
       dragProgress.set(0) is called by parent
       The new back card starts at peeking position again

PART 9 — REACT NATIVE IMPLEMENTATION NOTES
================================================================================

Replace every Framer Motion primitive with react-native-reanimated v3:

  useMotionValue(0)             → useSharedValue(0)
  useTransform(x, in, out)      → useDerivedValue(() => interpolate(x.value, in, out))
  motion.div style={{ x, rotate, opacity }}  → Animated.View with useAnimatedStyle
  useAnimate()                  → useAnimatedStyle + withTiming / withSpring
  drag="x", onDragStart, onDrag, onDragEnd
    →  PanGestureHandler from react-native-gesture-handler
       onGestureEvent: update x.value = event.translationX
       onHandlerStateChange: check state === END, run commit or reset logic

  animate(ref, { x: exitX, opacity: 0 }, { type: "tween", duration, ease })
    → x.value = withTiming(exitX, { duration: ms, easing: Easing.bezier(0.25, 0.46, 0.45, 0.94) })
      then opacity.value = withTiming(0, { duration: ms })

  dragElastic: 0.18
    → When card is past constraints, multiply offset by 0.18 for resistance effect

  spring stiffness: 350, damping: 35
    → withSpring(0, { stiffness: 350, damping: 35 })

  AnimatePresence with initial y:"100%" animate y:0 exit y:"100%"
    → Use a boolean state to conditionally show the overlay.
      On show: translateY.value = withSpring(0, { stiffness: 350, damping: 35 })
      On hide: translateY.value = withSpring(screenHeight, ...)
      Use Animated.View wrapping the overlay content.

  The info overlay drag-to-dismiss:
    → Separate PanGestureHandler tracking vertical direction only.
      If gesture ends with translationY > 80: dismiss.
      Otherwise: reset translateY to 0 with spring.

Key RN-specific considerations:
  - Use Dimensions.get('window').width instead of window.innerWidth for THRESHOLD.
  - THRESHOLD = screenWidth * 0.27 (same ratio, just different source).
  - Haptics: expo-haptics ImpactFeedbackStyle.Light instead of navigator.vibrate(12).
  - Images: use <Image source={require('../assets/images/...')} resizeMode="cover" />.
  - The "drop-shadow filter" CSS → use shadow props on the icon's container View.
  - mix-blend-mode: overlay has no RN equivalent — omit the parchment tint overlay
    or approximate with a very low opacity solid color View instead.
  - The drag layer (invisible draggable area covering top portion of card) →
    in RN this is just the PanGestureHandler area. Set the gesture's hitSlop
    to exclude the bottom 128px where buttons live.
  - touchAction: "pan-y" → handled automatically by RN gesture system.
